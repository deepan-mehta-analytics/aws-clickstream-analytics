# Data Dictionary

Every table and column in the pipeline, with its meaning in plain words.
The design is in [ADR-0003](adr/0003-data-model.md).

**Origin** says where a value comes from:
- **real**: taken from the UCI #553 source file (see
  [`data/README.md`](../data/README.md));
- **derived**: calculated from real values;
- **synthetic**: generated by us, because the source lacks it; every
  such column ends in `_synthetic`;
- **pipeline**: recorded by the pipeline itself.

**Role** gives each table's star-schema role, so the plain table names
stay readable without prefixes such as `fact_` or `dim_`.

Status: **designed, not yet built.** Types are the intended Parquet and
Redshift types.

---

## Source field mapping

| Source column (UCI) | Plain name | Meaning |
|---|---|---|
| `year`, `month`, `day` | `click_date` (from Silver on) | Date of the click (2008-04-01 to 2008-08-13) |
| `order` | `click_number_in_visit` | 1 for the first click in a visit, 2 for the next, and so on |
| `country` | `country_code` | Country of the visitor's IP address (1–47; the codebook is in `countries`) |
| `session ID` | `visit_id` | One browsing visit (the source calls it a session) |
| `page 1 (main category)` | `category_code` → `category` | 1 trousers, 2 skirts, 3 blouses, 4 sale |
| `page 2 (clothing model)` | `product_code` | Product code, such as `A13` (217 products) |
| `colour` | `colour_code` → `colour` | 14 colours |
| `location` | `photo_position_code` → `photo_position_on_page` | Where the product photo sat on the screen: 6 positions (top left … bottom right) |
| `model photography` | `photo_angle_code` → `photo_angle` | 1 front, 2 side (the source says "en face" and "profile") |
| `price` | `price_usd` | Price in US dollars |
| `price 2` | `price_above_category_average_code` → `priced_above_category_average` | Whether the price is above its category's average (1 yes, 2 no) |
| `page` | `page_number_in_shop` | Which shop listing page (1–5) the product appears on |

## Bronze

### `clicks_received`: one row per click as it arrived (resends possible)

| Column | Type | Origin | Meaning |
|---|---|---|---|
| `click_id` | string | derived | Same value every time the same click is replayed, built from `visit_id` and `click_number_in_visit`. Used to remove duplicates |
| `visit_id` | bigint | real | Source session ID |
| `year`, `month`, `day` | int | real | Source date parts, kept raw |
| `click_number_in_visit` | int | real | Source `order` |
| `country_code`, `category_code`, `product_code`, `colour_code`, `photo_position_code`, `photo_angle_code`, `price_usd`, `price_above_category_average_code`, `page_number_in_shop` | as source | real | Raw codes, not yet decoded |
| `click_time_synthetic` | timestamp (UTC) | synthetic | The real date plus a generated time of day |
| `device_type_synthetic` | string | synthetic | desktop, mobile or tablet, one per visit |
| `received_time` | timestamp (UTC) | pipeline | When the event reached Kinesis or S3 |
| `data_source` | string | pipeline | Always `uci553` |

Partitioned by the UTC `year/month/day/hour` folders Firehose writes when
the event is received.

## Silver

### `clicks`: one row per real click, cleaned

| Column | Type | Origin | Meaning |
|---|---|---|---|
| `click_id` | string | derived | Unique; duplicates are removed |
| `visit_id` | bigint | real | Which visit the click belongs to |
| `click_number_in_visit` | int | real | Position of the click in its visit |
| `click_date` | date | real | Date of the click |
| `click_time_synthetic` | timestamp (UTC) | synthetic | Generated click time |
| `click_hour_shop_time_synthetic` | int | synthetic | Hour of day (0–23) in shop local time (Europe/Warsaw) |
| `product_code` | string | real | Product clicked |
| `category` | string | real | Decoded category name |
| `colour` | string | real | Decoded colour name |
| `price_usd` | int | real | Price in US dollars |
| `priced_above_category_average` | boolean | real | Decoded yes/no |
| `page_number_in_shop` | int | real | Listing page, 1–5 |
| `photo_position_on_page` | string | real | Decoded screen position |
| `photo_angle` | string | real | front or side |
| `country_code` | int | real | Visitor country code |
| `device_type_synthetic` | string | synthetic | Visitor device |
| `received_time` | timestamp (UTC) | pipeline | When the event arrived |
| `seconds_late` | bigint | derived | `received_time` minus `click_time_synthetic`; in a replay, this measures the replay delay |
| `click_month` | string (`YYYY-MM`) | derived | Partition column |

### `clicks_rejected`: rows that failed a hard quality rule

All `clicks_received` columns, plus `rejection_reason` (which rule
failed) and `rejected_time` (when). No row is dropped silently.

## Gold

### Reference tables (star-schema role: dimension)

| Table | One row is… | Columns |
|---|---|---|
| `products` | one product (217) | `product_code`; `category` (the most frequent one; A18 → trousers); `colour`; `price_usd`; `priced_above_category_average`; `page_number_in_shop`; `photo_position_on_page`; `photo_angle` |
| `countries` | one country code (47) | `country_code`; `country_name`; `kind` (country, web domain such as `.com`, or unknown) |
| `calendar_days` | one date | `calendar_date`; `day_of_week`; `week_number`; `month_name` |
| `devices` | one device type (synthetic) | `device_type` |

### Event tables (star-schema role: fact)

**`clicks`: one row per click (165,474 expected)**

`click_id`, `visit_id`, `click_number_in_visit`, `click_date` →
`calendar_days`, `click_time_synthetic`, `product_code` → `products`,
`country_code` → `countries`, `device_type_synthetic` → `devices`,
`price_usd`, `click_month` (partition).

**`visits`: one row per visit (24,026 expected)**

| Column | Origin | Meaning |
|---|---|---|
| `visit_id` | real | The visit |
| `visit_date` | real | Date of the visit (visits never cross midnight) |
| `country_code`, `device_type_synthetic` | real / synthetic | Visitor country and device |
| `visit_start_time_synthetic`, `visit_end_time_synthetic` | synthetic | First and last click times |
| `visit_length_seconds_synthetic` | synthetic | End time minus start time (0 for a one-click visit) |
| `clicks_in_visit` | derived | Number of clicks |
| `products_viewed` | derived | Distinct products clicked |
| `categories_viewed` | derived | Distinct categories clicked |
| `deepest_page_reached` | derived | Highest `page_number_in_shop` reached (the browse-depth funnel stage) |
| `bounced` | derived | True if the visit had exactly one click |
| `first_product_viewed`, `last_product_viewed` | derived | Entry and exit product |
| `visit_month` | derived | Partition column |

### Dashboard summaries

| Table | One row is… | Used for |
|---|---|---|
| `daily_visits` | one date | Visits, clicks, bounce rate per day |
| `visit_depth_funnel` | one shop page (1–5) | Visits reaching at least that page (expected 24,026 / 14,504 / 9,125 / 4,779 / 1,631) |
| `bounce_rate_by_product` | one product | Visits that started on the product, and how many bounced |
| `visits_by_country_and_device` | one country × device | Visit counts; device is labelled synthetic |

In Athena these are views; in the Redshift window they are materialized
views. They are exported with `UNLOAD` to form the published Streamlit
snapshot.
